```
LAS ──► 单位归一 ──► 伽玛族通道(GR/GR_NOU/KTH/CGR/SGR) ──► VSH 定源(权威列)
```

## 2. 泥质含量（VSH）

### 2.1 定源机制（先择优，再定源）

- **候选池** `audit_vsh_methods`(3031)：伽玛族四变换（`larionov C=2` / `C=3.7` / `linear` / `stieber`，驱动通道 GR / KTH / GR_NOU）+ 元素标定（`elem`）。**交叉验证项**（密度-中子 `dn`、声波 `dt`、电阻率 `rt`、SP、单中子）**不参与胜出**。
- **打分** `_vsh_score`(2999) = `0.35·r + 0.20·mono + 0.15·range_norm + 0.15·sat_norm + 0.15·cov_norm`（权重 `_VSH_AUDIT_WEIGHTS` 2913）。
- **硬门槛** `_vsh_gates`(3011) / `_VSH_AUDIT_GATES`(2914)：`cov≥0.30`、`range≥0.08`、`sat≤0.30`、`r≥0.30`、`mono≥0.75`。
- **择优纪律**(3200–3238)：**在位者优先**；挑战者须 `score ≥ 在位×1.10`（`vsh.auto_select_margin`）才换。只有 `family ∈ ('gr','elem')` 有资格胜出。
- TrakesKE-1 结果：**GR-Larionov(C=2)** 在位，总准 86.9% 未回退。

## 3. 岩性识别（LITHOLOGY）

主函数 `classify_lithology`(13993 类方法；内联 row 版 12686)，调用 14486（经 `data.apply`→13146）。

**判定优先级**：

1. **特殊矿物** `detect_special_mineral`(12734) 最先 —— 密度>2.68 & PE>3.5 → 白云石/灰岩；PE>5.0 & NPHI<15 & AC<65 → 灰岩。
2. **泥质主导泥岩**(12810)：`vsh_ref ≥ shale_cut`0.5 **且** `vsh_ref ≥ _vcarb_eff + 0.10`。其中碳酸盐有效体积用**密度自洽门**：骨架下限 `2.71·vcarb + 2.60·(1−vcarb) − carb_density_tol(0.15)`。
3. **多证据泥岩**(12848)：`shale_evidence.*` —— GR≥`gr_min`48 且（NPHI≥44 或 NPHI≥34 & DT≥125）；闸门 `carb_max`0.5 / `rhob_floor`1.90。
4. **矿物比例序**：硬石膏 / 盐岩 / 玄武岩 / 方解石 / 白云石 / 泥岩 / 石英（12939–12964）。
5. **岩性-泥质联动**(12746–12819、12956)：`vdolomite>0.5` 等分支；强判据保护位 `_vsh_strong`(13206)。

> **铁律**：护栏**不得推翻分类器强判据**。强判据点必须登记到 `_vsh_diag['strong']`，漏登记曾把总准从 86.9% 打到 66.5%（TrakesKE-1 3300→852 点）。

## 4. 孔隙度（PHI）

主管线 `calculate_porosity`(5113–5462)，`POROSITY_MAX = 0.4`(5154)。

| 方法                   | 公式                                                                    | 键                             |
| -------------------- | --------------------------------------------------------------------- | ----------------------------- |
| NMR 核磁               | `clip(nmr, 0, 0.4)`；`max>1` 时 `/100`                                  | `PHI_NMR`                     |
| M1 密度（泥质校正）          | `(DM−RHOB)/(DM−DF) − VSH·(DM−DSH)/(DM−DF)`，`DM`2.65/`DF`1.0/`DSH`2.45 | `PHI_DEN_SHALE`               |
| M2 声波 Wyllie         | `PORA=(TC−TM)/(TF−TM) − VSH·(TSH−TM)/(TF−TM)`；`Cp` 随深度压实校正            | `PHI_SONIC_SHALE`             |
| M3 中子                | `(CNL−NM)/(NF−NM) − VSH·(NSH−NM)/(NF−NM)`，`NM`−2/`NF`100/`NSH`35 pu   | `PHI_CNL_SHALE`               |
| M4 中子-密度加权           | `((PORN+PORD)/2 + √((PORN²+PORD²)/2))/2`                              | `PHI_ND_WEIGHTED`             |
| M5 交会图岩性加权           | `c₁·PORN + c₂·PORD`（砂岩 0.4/0.6、泥岩 0.6/0.4、灰岩 0.5/0.5、白云岩 0.6/0.4）     | `PHI_CROSS_LITHO`             |
| M6 算术平均 / M7 中子-声波几何 | `(PORN+PORD)/2` / `√((PORN²+PORA²)/2)`                                | `PHI_ND_MEAN` / `PHI_NS_MEAN` |
| 多矿物反演                | SLSQP，`PHI = best_result.x[-1]`(8980)                                 | —                             |

**选择优先级**(5361–5412)：砂泥岩 `PHI_NMR > PHI_DEN_SHALE > PHI_ND_WEIGHTED > …`；碳酸盐岩 `PHI_NMR > PHI_ND_WEIGHTED > PHI_CROSS_LITHO > …`。逐点取首个正值，并 `min(val, 0.4)`。

**岩性自适应骨架值**：仅在反演内部 `matrix_densities`(8381–8388) —— 砂岩 2.65 / 灰岩 2.71 / 白云岩 2.87 / 泥岩 2.55 / 硬石膏 2.98，`fluid_density=1.0`。**盐岩(2.03) 未定义**，落入按 RHOB 分档的兜底 → 虚高（上游 17749 有补丁归零）。

**孔隙度下限门**：解释层内 `interpretation.min_porosity`=0.08（碳酸盐 0.06）；过度解释修剪 `over_interp.hc_min_porosity_sand/carbonate/silty` = 0.10 / 0.07 / 0.12；层表最终门 water 段中位 <0.07（碳酸盐）/0.10 → NonReservoir。⚠️ `porosity_threshold`=0.05(6790) **配置存在但无消费者**。

## 5. 含水饱和度与 Rw

### 5.1 Sw

**本系统 Sw 只有 Archie 一条主线**，无印尼式 / Waxman-Smits / 双水。

- `calculate_saturation`(10844–11117)：`Sw = (a·Rw / (φᵐ·Rt))^(1/n)`(11084)，`archie.a/m/n` = 1.0/2.0/2.0。
- 收尾：`φ<0.001 → Sw=0`；`So = 1−Sw`；`Sg = 0`；`VALID_CURVES_COUNT<3 → NaN`。
- **重算两次**：第一遍 12093（此时 PHI 是反演占位值）→ **第二遍 15869 用最终 PHI 覆盖**（用户口径："饱和度必须与最终孔隙度同体系"）。
- 死代码：`calculate_water_saturation`(5464) **全库无调用**；15883–15904 硬编码兜底分支正常流程不触发。

### 5.2 Rw 优先级链（高 → 低）

1. **显式 `archie.rw_profile`**（md/Rw 锚点，对数线性内插，clip[0.005,10]）10919–10936
2. **自动剖面** `_build_rw_profile_from_water_layers`(10627) —— 默认 `estimator='window'`，走 **滑动窗口 Pickett 下包络** `pickett_windowed_rw`(3337)：逐窗取 `φᵐ·Rt/a` 的 **p15 低分位**；窗宽 30 m / 步长 15 m；门 `phi_cut`0.10、`anchor_vsh_max`0.40
3. `archie.formation_windows` 分层 Rw/m/n 10988–11008
4. 单值决策：`_auto_detect_Rw`(10527)（√Rw 累计频率 50%）vs 区域值
5. 默认 `archie.Rw` = 0.05

**区域 Rw**：`regional_rw_profile` > `regional_rw` > 知识库氯根换算（`rw_from_chloride` 3422：`Rw@75F = 0.0123 + 3647.5/(1.645Cl)^0.955`，再温度校正）> `regional_rw_from_kb`(3461) 标 `kb_analog`。**对比只记录不改值**（`compare_rw_with_region` 3551，tol_factor 2.0）；区域与反算冲突过大时**以反算为准**。

> ⚠️ **"剖面算两遍取后一遍"的坑**：窗口法在 PHI 为占位值（偏大）时会给出虚高 Rw（实测深部 38 Ω·m，真值 2.6–4.7）。代码用 `_rw_profile_auto_cache` 比对两遍并默认取新(10899)，**但当后一遍退化（跨度 < 旧的一半 或 锚点数 < 旧的一半）时静默保留前一遍** —— 即重新引入虚高。**此处必须审计。**

### 9.2 结构性约定（建议固化）

1. **单点写入口**：所有改写 VSH 的操作必须走统一函数，并登记"谁改的 / 为什么 / 段范围"，否则无法排查"改了被覆盖"。

4. **配置访问统一走一个 config 访问器**，消除 `FaciesAnalyzer` / visualizer 的死角。

## 11. 决策记录


### 11.1 已决策（2026-09-23，用户口径）

1. **`PHI` 的 0.4 上限饱和段 —— 不做保形状压缩，它是端元值。**
   用户口径："PHI 的 0.4 上限饱段是不要保形状压缩，这是端元值。"
   理由：0.4 是孔隙度**物理上限**，顶到边界就只能不变；与 `VSH` 的 0.35 封顶性质不同——后者 0.35 不是边界而是人为 cap，故必须压缩。
   **现状（无需改动）**：`_enforce_component_shape` 的处理列只有 `VSH` 族 / `VClay` / `VQuartz` 及碳酸盐矿物，**`PHI` 不在其中**，天然豁免。全井扫描确认 `PHI` 常数段 **77 个全部是端元**（0 = 非储层归零；0.40 = 上限），**中间值 0 个**（其中 0.4 段 12 个、集中在 605–772 m 浅部）。
   ⇒ 仅在形状自检里保留"告警列出"，不做任何数值干预。

2. **`GR_NOU` 口径全井推广 —— 已实施，并加能谱缺失降级链。**
   用户口径："GR_NOU 口径全井推广，但有的井没有 K，U，TH 等伽玛能谱测井数据。"
   实施（`logInt.py` 597–650）：`GR_NOU = 16.32·K(%) + 3.93·Th(ppm)`；**单位自适应**（K 中位 >50 判为 ppm ⇒ ÷10000；0 < Th 中位 <0.5 判为 % ⇒ ×10000）；**降级链** `K+Th 能谱 → CGR(去铀伽玛) → 不建列`（三档皆缺则伽玛族回退总伽玛 `GR`）。
   验证：本井 `GR_NOU` 中位 **10.37 → 48.28**（与 GR 中位 43 同量纲），与 LAS 的 `CGR` 相关 0.859；端到端 5 例测试（`_test_grnou_fallback.py`）全通过。
   本井实证"部分井段无能谱"：`POTA/THOR` 仅 **584.9 m 以下**有效（7850/13402 点），585 m 以上自动回退 `GR`，不报错、不误用混用算式。

3. **`seal_reclass.gr_ratio` —— 不拍固定值，改为随全井伽玛起伏自适应。**
   用户口径："全局默认要不要从 1.10 提到 1.25 还需要考虑全井伽玛的起伏幅度。"
   实施（`logInt.py` `_reclassify_seal_as_shale`）：`gr_ratio` 给数字 = 手工钉死（优先）；**缺省/null = 自适应**
   `gr_ratio_eff = clip(1 + gr_z_min·σ_GR / gref, gr_ratio_min, gr_ratio_max)`，其中 `σ_GR = (P84−P16)/2`（QC：0<GR<500 且非套管/水泥段），含义 = "段 GR 中位须高出邻域孔隙层 `gr_z_min` 个全井伽玛尺度"。默认 `gr_z_min`0.6 / `gr_ratio_min`1.15 / `gr_ratio_max`1.80。
   验证：本井 σ_GR = **23.34**，各段门 **1.268 ~ 1.319** —— 结论与手工 1.25 一致，且**多识别出 688.4–689.7 m 一段真泥岩**（真值 680.0–694.0 m 浅灰色泥岩）；四段真值（688.4 / 1078.6 判泥岩；1177.8 / 1248.4 拦下）**全部判对**。

4. **非储层物性归零 —— 统一为"只按岩性归零"，五处同源。**
   用户口径："三处口径统一成'只按岩性归零'，650–736 m 判 `NonReservoir` 不合理，本是高孔砂岩，肯定是储层。"
   语义分层原则：**"储层/非储层"由岩性 + 物性决定，不能由流体结论（`NonReservoir`/`WATER`/`OIL`）反推。**
   实施：新增模块级单一口径 `NONRESERVOIR_SEAL_LITHS`(15010，泥岩/页岩/粉砂质泥/煤/膏盐/火成岩/基底 等) + `_mask_nonreservoir_seal`(15028) + `WellLogProcessor._nr_lith_mask`(15146)；
   五个执行点全部改走该掩膜：① 16634（非储层归零，`LITHOLOGY` 缺失时才退回按结论 + `warning`）② 17026 ③ 17050（分层回填后）④ 17569（`_prune_over_interpretation` 写回，**调用点 16836**）⑤ 17751（`_apply_gas_and_prior_constraints` 写回，**调用点 16849**）。

   **验证（XIMENIA-5）**："`PHI` 被抹 0 而 `PHI_LOG` 有值"的点数 **6289 → 0**；1103–1140 m 由 `NonReservoir×401 → WATER×394`，`PHI` 中位 **0 → 0.2928**（该段 `PHI_LOG` 中位 0.2718、`PERM` 中位 103.9 mD）。

   **幂等性**：与受控实验版逐列差异 **0**（`INTERPRETATION`/`LITHOLOGY`/`PHI`/`Sw`）。
   > **备注（另一处同语义实现，本轮未改）**：`MineralAnalyzer.apply_non_reservoir_phi_zeroing`(9679，调用 12143，在 `calculate_saturation` **之前**) 也做"非储层 `PHI/Sw/So` 归零"，但它**本来就只按岩性/VSH**（`exclude_liths` 局部表 + `_SHALE_LITHS` + `VSH>=shale_cut`），语义正确。

6. **归零口径补漏：层表 `_emit` 的 `SW_MEAN` 也按岩性归 0。**（2026-09-23 第二轮）

8. **"非储层" = 纯岩性，不设物性门；岩性不被物性门槛改写。**（2026-09-23 第三轮，用户拍板）
   用户原话："'**非储层**' = 纯岩性，储层物性小于截止值的**不是有效储层**，所以不加物性门 —— 因为还会有后续的非储层需要用**主要岩性填孔隙**，那会反过来影响岩性结论，所以不加物性门，**保持岩性不变**。"
   **语义分层（不可混）**：
   - **"非储层"（岩性概念）** = `NONRESERVOIR_SEAL_LITHS` 白名单 ⇒ 决定 `PHI/Sw` 是否归 0、矿物是否重分配、岩性是否改写；
   - **"非有效储层"（物性概念）** = 流体结论 `NonReservoir`/`TIGHT` ⇒ **只影响流体结论**，不回写 `LITHOLOGY`、不触发矿物重分配、不据以归零物性。
   理由（用户给出，且与代码互证）：`run_mineral_analysis`(10183，"泥岩/盐岩/硬石膏等非储层孔隙度归 0，其空出部分由**主要岩性填充**") 与 `apply_non_reservoir_phi_zeroing` 的"非储层矿物重分配"都**按岩性**触发；若把物性门槛并进"非储层"，这些点的孔隙体积会被主矿物吸收 ⇒ **反过来改写岩性结论**。
   实施（**无行为变更，仅固化政策**）：① 模块级注释增补语义分层与禁令（15002–15027）；② 新增政策护栏 `_guard_nr_property_gate`(15072)：`non_reservoir_zeroing` 下若出现 `phi/poro/perm/cut/thresh` 之类键 ⇒ **告警并忽略**（每进程一次）；③ `logint.json → non_reservoir_zeroing` 显式落盘策略注释 + `extra_seal_liths: []`（该键**只**用于追加岩性名）。
   核验：新增 `_audit_nr_lith_only.py`（源码锚点 + 配置 + 点级，三重核验 → `_audit_nr_lith_only.txt`）。
   **结果（XIMENIA-5 / TrakesKE-1）**：
   - **A 源码**：6 处归零点（①16757 ②17089 ③17100 ④17642 ⑤17804 ⑥9746）掩膜**全部来自岩性白名单**；反向扫描**无"按结论"归零残留**；
   - **B 配置**：`non_reservoir_zeroing` 下**无物性阈值键**；
   - **C 数据**：非储层岩性点 `PHI=0` / `Sw=0` 均 **100%**；**储层岩性 & 结论 `NonReservoir`** 的点 —— XIMENIA-5 **1028 点保留真实物性（`PHI` 中位 0.0462，其中 99.5% 的 `PHI>0`）**、TrakesKE-1 **18 点（`PHI` 中位 0.1661，100% `PHI>0`）**；「`PHI=0` 而 `PHI_LOG>0`」全井 **0 点**。
   ⚠️ **登记一处既有物性代理门（未改，供知悉）**：`calculate_saturation`(11143/11155) 用 `phi_zero_mask = PHI < 0.001` 把 `Sw/So/Sg` 置 0。它执行于**任何解释结论产生之前**，且此刻 `PHI` 只被岩性（膏盐/煤/火成岩/泥岩）归 0 ⇒ 实质是"该点无有效孔隙 ⇒ 不给饱和度"；又因 Archie 侧已把 `φ<0.001` 置 `NaN`，删掉该行会经 `So = 1 − Sw` 产出**"假纯油"**（§10 P0-5），故**保持现状**。

### 11.2 仍待决策

1. **点级 `So` 归零覆盖不全**：仅覆盖"岩性型非储层"，TrakesKE-1 仍有 **153 个砂岩点 `So>0`**（层表不受影响，因层表侧 `_emit()` 强制非储层层 `PHI_MEAN=SW_MEAN=0`）。**本轮保持现状、未动**；如需消掉这 153 个点请明确指示。

2. **`_reclassify_seal_as_shale` 的孔隙度判据用了"会被归零的列"** —— 待业务定夺。
   现状：`phi_use = np.where(np.isfinite(phi), phi, plog)` 优先用 `PHI`，而 `PHI` 在非储层段会被归 0，与项目既定口径"物性门槛须用**从不归零**的连续列（`PHI_LOG`/`PHI_DEN_SHALE`）"矛盾。
   **后果分两面**：
   - TrakesKE-1 `688.4–689.7 m` 真泥岩此前能被召回，靠的正是该段 `PHI` 被归 0 后"误打误撞"满足判据③（自身无孔隙 < `phi_cut` 0.10 —— 而该段 `PHI_LOG=PHI_DEN_SHALE=0.202–0.235`，真实有孔隙）。
   - 改用从不归零的列后，该段**不再召回**，岩性总准 **87.3% → 86.8%（−0.5%）**。
   **若需召回**，建议另立显式规则："高伽玛（`GR > 邻域孔隙层 × gr_ratio_eff`）且 `VSH ≥ 0.45` ⇒ 判泥质岩"，而不是依赖孔隙度被归零的副作用。
   （注：本轮未改动此处逻辑，仅记录暴露出的缺陷。）
   **与 §11.1-8 的关系（厘清，避免误判为"用物性改岩性"）**：`phi_cut` 在此处是**位置判据** ——
   用来圈定"夹在两段孔隙层之间、自身无孔隙"的候选段；**岩性改写仍必须另有泥质证据**
   （判据⑤：段内 `VSH` 中位 ≥ `vsh_min` **且** `GR` 中位 ≥ 邻域孔隙层 × `gr_ratio_eff`）。
   即"孔隙度低"本身**判不出**泥岩，只是限定候选位置 —— 与用户"保持岩性不变"不冲突。
   仍待定的只是：`phi_use` 该不该改用**从不归零**的连续列（`PHI_LOG`/`PHI_DEN_SHALE`）。

3. **XIMENIA-5 结论分布大改，是否需在有试油结论的井上复核** —— 24660 点中 **6658 点 `NonReservoir → WATER`**。

4. ~~**"非储层"的定义是否只含岩性（不含物性门）**~~ —— **✅ 已决策（2026-09-23）：不加物性门，详见 §11.1-8。**
   保留此条仅为留痕：当时待定的"砂岩但 `PHI` 低于岩性下限，是否也应归 0"已被用户否决 ——
   "储层物性小于截止值的是**非有效储层**"，语义上属**流体结论**层，不并入"非储层"定义，

### 14.1 修掉静默 Bug：`np` 被局部导入遮蔽

`run_workflow`(15710) 函数体第 **16173** 行有一句冗余 `import numpy as np` ⇒ Python 把 `np`
判为该函数**局部名** ⇒ 同函数中位于其**之前**的第 **16068** 行 `np.median(...)` 抛
`UnboundLocalError`，被 `try/except` 吞掉，只留一条
`WARNING - PHI_LOG 快照失败(跳过): cannot access local variable 'np'`（自 `_run_gas*` 系列日志起一直存在）。

- `data['PHI_LOG']` 在 16064 行**已赋值**（快照本身成功），仅那条 INFO 日志从未打印；
- 真雷是**"函数前段一切 `np.*` 一律不可用"** —— 日后在前段新增 `np.` 调用会静默失效。
- 修复：删该局部导入（模块级 L218 已有）。验证：告警 2→**0**、`PHI_LOG 已快照` INFO 0→**2**，结果 `ALL_SAME`。
- **教训**：函数内任何 `import x as y` 都会把 `y` 变成**全函数局部名**；
  `UnboundLocalError` 被 `except Exception` 捕获后**只留 warning**，极易长期潜伏。
  排查此类问题时优先 `awk` 扫描"函数体内、使用点**之后**的局部 import"。
