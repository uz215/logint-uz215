# 智能测井解释系统 — 程序架构与产品路线（2026-11-01 用户定案）

## 1. 程序集（只有这些是"程序"，不再新增程序）

| 程序 | 职责 | 主要入口 |
|---|---|---|
| **logInt.py** | 主解释程序：数据加载→清洗→QC→岩性→流体→唯一裁决→层表→解释/可视化/报告；含 **quicklook** 与 **综合解释图** 两种出图功能 | 交互菜单 / `--quicklook` / 批处理 |
| **logKnow.py** | 知识库：文档入库、检索、案例/条款/事实、长期积累 | 知识库界面/命令行 |
| **logGraph.py** | 知识图谱：实体/关系/图谱查询 | 图谱界面 |
| **logvis.py** | 可视化引擎：quicklook 图、综合图、交汇图、报告配图 | 被 logInt 调用（唯一图引擎） |
| **Gas.py** | 气测解释程序：**C1–C5** 组分解释 | 气测解释界面 |
| **Flair.py** | 气测解释程序：**C1–C8** 组分解释 | 气测解释界面 |

## 2. 内部库（不是程序、没有独立入口）

`logsys/*` 是上述程序的内部库，只被程序调用，不单独交付、不单独运行：
- 数据与解释：`layers`、`calibrate`、`fluidml`、`pipeline_ml`、`wellcal`、`arbiter`、`evidence_stack`、`zonation`、`regions`、`mixed_split`、`fluids`、`sufficiency`；
- 井文档：`well_docs`（地质设计/录井图/甲方格式唯一解读）、`masterlog`（录井图底层解析，仅 well_docs 调用）、`truth_lith`、`region_lith`、`lithcal`、`lith_validate`；
- 知识：`knowledge/*`（db/ingest/build/query/cases/clauses/...）；
- 质量：`acceptance`、`regress`、`golden`、`golden_report`、`run_manifest`、`status`；
- 报告：`kb_decide`（决策记录 + 完整报告，由 logInt 调用）；
- 项目工作台：`project_config`（项目与井登记/源资料绑定）、`project_model`（项目树扫描与井状态）、`project_job`（子进程作业执行与产物归集）、`project_browser`（工作台 GUI，唯一入口界面）。

> 原则：**新功能只加为现有程序的库/选项，不新增程序或独立 GUI**。

## 3. 功能选择（现状与规划）

现状（logInt 内）：
- **无参数启动 → 唯一「项目工作台」**（R75 起）：进入项目 → 选中井 → 执行作业，不再有前置任务选择界面；
- 井级作业（项目内右键井触发）：
  - **quicklook**（快速解释图）：现场测井工程师快速出图，交甲方业主现场代表；
  - **综合解释**（岩性/流体/层表/综合图/报告）：室内解释工程师，成果作报告附件；
- 脚本通道保留：`--quicklook <井目录>`、`--project <项目根>`、直传 LAS；
- 主流程：综合解释、层表生成、决策记录与完整报告（PDF/HTML，作为报告附件）；
- 井 `info.json`：解释来源/解释截止值/解释井段/区域知识/地质设计/录井图/甲方格式/解释参数（气油比例、干层含烃）。

规划（Techlog 式统一界面）：
- 在项目工作台内补齐：报告任务、知识库入库、知识图谱、气测解释（Gas C1–C5 / Flair C1–C8）、批量运行；
- 各任务复用同一套内部库与同一份成果（一处确定，避免多头）。

## 4. 产品定位

- **quicklook**：现场测井工程师快速出图，直接交甲方业主现场代表；
- **综合解释图**：室内解释工程师综合成果，作为报告附件提交；
- **知识库/图谱**：长期积累（跨国家、跨区块、案例/条款/事实），逐步提高自动化与准确率；
- **当前主要工作**：把系统建成健康、可交付的产品（数据契约、唯一裁决、回归测试、报告可追溯），再在此基础上不断完善。

## 5. GAS_OIL 与干层口径（用户定案）

- **GAS_OIL = 油气同层**：层内油气比例大体相当，测试时油气同出；默认 Sg/So 各半（0.5/0.5）；
  如实际测试比例不同，可在 `info.json → 解释参数.气油比例` 指定（0.4=气占40%/油60% 仅为示例，不是固定规则）；
  不用气测组分自动推断饱和度比例（组分≠地下含烃比例）；
- **干层 DRY**：物性/可采性差不产，但**不是不含油气**；仍按 1−Sw 计算 Sg/So（气油分配按图版/比例）；
- 守恒：SG + SO + SW_EFF = 1。

## 6. 集成原则

1. 地质设计/录井图/出图格式解读只在 `well_docs` 一处，其它程序只调用；未选择时井目录查找，找不到跳过；
2. 解释结论只在 `arbiter` 一处裁决，层表/点数据/图/报告/验收同源；
3. 新增能力优先做成现有程序的选项，不新增程序；Gas/Flair 的 C1–C5/C1–C8 解释逻辑与 logInt 共用气测图版库（逐步融合）；
4. 每次改动跑契约/报告黄金/回归/验收，保持可交付。


## 7. 唯一项目工作台与"井包"规范（R74~R76 落地）

### 7.1 项目工作台（logInt 无参数启动即进入，唯一入口界面）
R74 起「项目在前」：顶层不再并列 quicklook 任务，作业下沉为**项目内的井级动作**；
R75 起原「任务与数据选择」界面与项目浏览器合并为**唯一的项目工作台**，启动即工作，无前置对话框。

工作台结构：
1. **项目根**（默认取仓库 `output/`）：项目树根节点即项目；
2. **项目成员** = 已登记的井（`project.json` 的 wells）∪ 产物目录 `output/<井名>/` 下的子目录；
   —— 从没解释过的新井**也能进项目**（R76「添加井到项目」），登记即成员，无需先有产物；
3. **井状态双维度**：产物完成度（complete/partial/pending/empty）× 源资料是否关联（已关联/缺源）；
4. **井级动作**（右键井）：快速解释图 / 综合解释 / 关联原始资料目录 / 指定主 LAS / 指定气测文件 /
   选择甲方出图格式 / 重命名井 / 从项目移除；
5. **项目级动作**（右键项目根）：添加井到项目 / 批量添加井；
6. **资料绑定**：井 ↔ 原始资料目录由 `project.json` 显式绑定（`project_config`），不靠文件名猜；
   手工指定优先于自动探测；井级可指定 `las`/`gas`/`config`；
7. **作业执行**（`project_job`）：子进程隔离解释流程与全局状态；产物按项目登记井名**归集**
   （修正 LAS 井名与项目登记名不一致导致的落盘目录名漂移），归集完成后井状态升级为「已解释」。

脚本通道（保留，供批处理与自动化）：`--quicklook <井目录>`、`--project <项目根>`、直传 LAS。

### 7.2 井包目录规范（建议固定）
```
<井名>/
  <井名>.las                  # 主测井数据（或 LAS 子目录）
  地质设计*.pdf/.md/.docx      # GTO/DWOP/钻探程序/中文设计
  *Masterlog*.pdf             # 录井图（岩性+气测异常+图头）
  气测*.xls/.las/.csv          # 数字气测（C1–C5 或 C1–C8）
  quicklook_config.json       # 甲方出图格式/图例（可选）
  <井名>info.json             # 可读可改配置（解释截止值/来源/井段/区域知识/地质设计/录井图/甲方格式/解释参数）
  （可选）试油/成果表          # 真值/标定/验收
```

### 7.3 智能流程（按资料与地质自动适配）
`井包清单 → 数据充分性门禁 → 知识库/区域规则 → 参数选择（info优先）→ 岩性 → 流体图版/规则/ML → 唯一裁决 → 层表/报告/图 → 不确定性复核清单`
- 缺数字气测：用录井图气测异常作证据（MASTERLOG_GAS）；
- 缺设计/录井图：跳过对应证据，不阻断；
- 数据不足：状态 INSUFFICIENT，结论仅供参考；
- 人工修改 info.json：下次运行优先采用。

### 7.4 知识闭环（长期）
- 解释成果 + 人工复核 → 案例层/事实/区域标定，逐步形成地区经验；
- 区域规则（岩性/流体/参数）按国家/区块积累，新井自动调用；
- 知识库/图谱作为 logKnow/logGraph 的长期资产，不另建程序。

## 8. 当前产品化优先级
1. 统一入口：**唯一项目工作台已落地**（R75），后续在其内补齐报告/知识入库/Gas·Flair/批量任务；
2. 交付物稳定：层表、综合图、报告（HTML/PDF）、决策记录、运行状态；
3. 质量门禁：契约/报告黄金/回归/验收；
4. 逐步补齐：报告任务、知识入库任务、Gas/Flair 融合、批量队列、Techlog 式界面。
