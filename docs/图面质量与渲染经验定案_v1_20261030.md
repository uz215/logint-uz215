## 1. 渲染架构不变量（改渲染链路前必读）

1. **分段唯一源**：岩性道与 PROFILE 特殊岩性整带共用 `_contiguous_lith_runs(lith_seq, valid_seq)`，
   禁止各自手写切分逻辑（两套切分必然不一致）。
2. **全局瓦片锚唯一**：`_tile_anchor = depth_min`（全图统一）。禁止 0 / z0 / md.min 混用——
   同一道内相邻段行线必须落在同一全局网格上（跨段接续对齐）。
3. **列相位全局锚定 x=0**（R22）：profile 道按 bounds 切分的子段各自起排瓦片会产生段界竖缝
   （用户反馈"错开的竖线"）→ 统一锚定后同道内所有段共享同一列网格。
4. **ref 瓦片 extent 必须覆盖完整格行**（R48）：`extent=[gx0, gx0+_cpx/hpx*dx, _z0c+_nr*dy, _z0c]`，
   可见性交给 clip_path。**严禁把 extent 按 z0/z1 裁剪**——那会把瓦片第 0 行锚到段边界，
   段高<1 瓦片格时每段只显示"瓦片顶部切片"或空切片（R48 根因，详见 §3-①②）。
5. **PROFILE 道矿物带/余量带符号整段一次绘制**（R50）：只按套管/窄带(<0.012)/岩性游程分段，
   **严禁按 bounds 漂移(>0.02)切 0.3-0.7m 子段逐块 imshow**——每块独立光栅化的亚像素相位
   逐块重置 → 跨块行距跳变（密集/稀疏伪迹）。可见性用 `_lith_clip_path` 逐点 bounds 线性
   多边形 PathPatch 精确裁剪（锯齿边界保留、符号不越入孔隙度留白）。
6. **格距只按设备像素密度**（R33）：dy=_th*scale，删除"巨型段放大格距"防御；内存防护由
   按行分块渲染（`_LITH_REF_MAX_PIX`）承担，块间共享全局网格（g0 行相位 + gx0 列锚）→ 跨块无缝。
7. **矢量/栅格符号 1:1 贴图**（R25/R26）：`_SYMBOL_REF_RASTER` 覆盖图按最终显示设备像素预采样
   （PIL BOX）+ nearest 贴图，消除 mpl antialiased 二次重采样把 2px 斜杠糊成 1px 灰线。
8. 四条不变量已写进 `draw_lithology_pattern` docstring，改函数先读。

## 2. 渲染问题排查方法论（先定量，再改码）

**步骤（每步都有实测教训）：**

1. **拿到版本与坐标**：确认用户看的是哪个 PDF（GUI 跑的版本在 `Desktop\output\`，CLI 跑的在
   `F:/360/src/output/<井名>/`，时间戳命名）。PDF 无文本层时，深度→pt 映射用**深度刻度数字序列
   标定**：沿深度道竖向采样窄条高清渲染→读数字→多点线性拟合（111D：`y = 1180 + (d-6440)*18.3333`，
   12 点验证）。**必须验证线性度，不能只拿图头 Start/Stop Depth 推算**（图头高度会引入偏移）。
2. **道布局实测**：渲染全宽整行（±300pt）确认每道 x 范围。坑：ViewImage 有显示缩放（1728→1080px），
   量道位置要除回缩放系数。
   **【R54 深度映射教训】刻度数字目检读数极易出错（6890/6900/6940 混淆、斜率读错）——
   正确做法=自动检测标签行 y 中心（黑色文本判据：RGB 通道差<45 且亮度<110，剔除竖线列，
   簇高 10-60px）+ 高清裁片批量读数 + 检验间距一致性（111D 实测 13.584pt/m，标签每 10m；
   此前 R50 的 18.333pt/m 是错的，导致"6785 井底"实为 6926m——被用户 6914m 火成岩反馈揭穿）。
   深度映射错了，一切"对深度"的定位/检测结论都会张冠李戴。**
3. **定量判据优先**：目检会骗人（砖纹"接近均匀"但实测空缺 47-187px）。
   - 行距均匀性：行墨迹>0.5×峰值的连续行段取中心→峰间距序列→CV、最大空缺（`_dbg/_r50_rowcheck.py`）；
   - **全段墨迹扫描不可靠**（混入曲线/边框噪声，R49 版 1063 个假"hot"行）；
   - 逐窗（80m 窗、10m 步）扫描，输出 FAIL 窗列表，新旧版本同口径对比。
4. **最小复现**：合成井局部渲染（`_dbg/_r49_clean.py` 模式），只画可疑岩性×厚度档，把现象
   从"真井数据+全流程"里剥出来。
5. **改码后必跑门禁+回归**：`_test_symbol_texture.py` → 综合图重出 → rowcheck 逐窗对比旧版 →
   另一口井（XIMENIA-5）回归确认无回归。

## 3. 三类图面缺陷档案（现象→根因→修复→检测）

### ① 只有底色、无纹理（R48，commit fbb67ed）
- **现象**：111D 综合图 PROFILE 道灰岩/白云岩大面积底色无纹理；岩性道交界处同样。
- **根因**：ref 瓦片分块渲染的 extent 被 `_rpx` 按 z0/z1 裁剪 → 瓦片第 0 行锚到段边界而非全局网格；
  段高<1 瓦片格（灰岩≈1.3m/白云岩≈2m）时显示瓦片顶部切片或空切片。
- **修复**：extent 覆盖完整格行 `[_z0c, _z0c+_nr*dy]`，可见性交给 clip_path；`_setup_profile_track`
  dy_r 兜底初始化。
- **检测**：门禁①整段墨迹总率 < TOTAL_MIN(0.01)；②内部 24×24px 格墨迹率 < CELL_MIN(0.015)。

### ② 一行有一行没有（R48/R49，commit cc7b7ea）
- **现象**：泥岩横线一行没一行。
- **根因**：同①的相位机制在薄段/互层处的表现。
- **修复**：R49 三件套（`_contiguous_lith_runs` 分段唯一源 / `_tile_anchor` 全图统一 / 门禁建立）。
- **检测**：门禁互层堆叠检查——1m 薄层交替带逐行中位色取墨迹，最长无符号空隙 >16px FAIL
  （健康 ≤10px）。注错演练：ref 不渲染→12 处 FAIL；忠实回滚 R48→56px 空隙 FAIL。

### ③ 间隔不一致/密集发黑（R50，commit 7269f3e）
- **现象**：111D 灰岩/白云岩几个小点突然密集成黑，或间隔突然变大（6493/6534/6629/6725 密集，
  6598/6602/6779 稀疏）。**只在 PROFILE 道矿物带**，岩性道行距完全均匀（CV≤0.022）。
- **根因**：矿物带按 bounds 漂移>0.02 切 0.3-0.7m 子段**逐块独立 imshow**——每块光栅化的
  亚像素映射相位逐块重置。实测（用户 GUI 跑的 084133 版）：正常行距 15.6px 基准下 47-187px
  空缺（6-12 倍行距），空缺两侧行挤紧=密集/稀疏交替。
- **修复**：去掉漂移切分；每游程整段一次调用 + `_lith_clip_path` 逐点多边形 clip；
  窄带守门(0.6×pitch)改用游程 max 宽。修复后 6505-6775 全 ok（剩余 3 窗 FAIL 为 basalt
  人字纹行结构/井底交界，属符号本身特性非缺陷）。
- **检测**：门禁 `row_spacing_check`——峰间距 CV>0.18 / 空缺>2.2×中位 / 粘连<0.45×中位 → FAIL。

### ④ 图例与实体不一致 / 点粘连（R19-R22 期间，详见符号绘制规则文档）
- 图例方框与道内实体必须同一核心（`draw_lithology_pattern_fig` 复用 `_lith_pattern_core`）；
  砂岩点 mew=0（默认 markeredgewidth=1pt 使点径 1+1=2pt≈点距，图例点粘连"大小不一致"）；
  微框（40×7.5pt swatch）用 motif=True 固定 4×2 格，按像素铺排退化成碎片。

### ④A 图头区边缘槽位刻度文字位置不一致（R55，111D TL 行文字坠线下方、BS/AT10/PE/TG 行抬离刻度线）
- **现象**：用户"第一道刻度（BS/AT10/PE/TG）首尾数字离刻度条距离略大，与其它刻度不一样；
  最后一个 TL 的刻度名和首尾数字应该在刻度条上面（现在坠到线下）"。
- **根因**：`draw_tick_labels` 的标签边界保护 clamp 用**图头高度 5% 比例余量**——本井
  12 槽 ×1.7cm ≈ 20.9cm 图头，5% ≈ 1.05cm，**超过边缘槽位到图头边界的空间（0.8cm）**：
  顶部槽位（TL，H−0.8cm，+0.05cm 偏移=H−0.75cm）被 clamp 压到 H−1.05cm → 坠到刻度线下方；
  底部槽位（0.8cm+0.05cm）被 clamp 抬到 1.05cm → 抬离刻度线约 0.25cm。中间槽位不触界，
  所以只有首尾行异常——**比例式边距在"高容器+边缘元素"场景必然吞掉贴线偏移**。
- **修复**：clamp 余量改**固定 0.1cm**（`_edge_ratio = 0.1 / HEADER_HEIGHT_CM_ADJUSTED`）。
  标签 `va='bottom'` 向上生长，正常永不触界，clamp 仅兜底——图头无需扩高。
- **教训**：①保护性边界 clamp 一律用**绝对物理量**（cm/px），不用容器高度百分比——
  百分比余量随容器增大而膨胀，反噬内容空间；②判断 clamp 是否该触发先算清
  "最坏内容位置+文字生长方向"（va='bottom' 向上、va='top' 向下）。

### ⑤ 火成岩 Γ 纹过密呈深色（R54，111D 6911-6945m basalt 段）
- **现象**：用户"6914m 火成岩纹理较密呈现明显的深色"。
- **根因**：basalt.png 参考图 96px 内含 **2×2 个 Γ**（单元 48px），旧链路把**整图**压进
  `_SYMBOL_REF_PITCH=28px` 的瓦片 → Γ 间距仅 14px（0.49m），墨迹率约为灰岩砖纹 2 倍——
  "格距 28"确认口径的本意是**一个 Γ 一个单元**，实现时整图当单元用了。
- **修复**：`_SYMBOL_REF_UNIT['basalt.png'] = (0,0,48,48,28,28)`——裁 1 个 Γ 单元缩到 28px，
  Γ 间距 14→28px（0.99m），实测自相关周期 28.0px ✓。
- **教训**：**注册特例格距前必须先量参考图内的 motif 网格数**——"格距"语义=一个 motif 单元
  的显示尺寸，不是"整张参考图缩到这么大"。多 motif 参考图（2×2/3×3）一律走
  `_SYMBOL_REF_UNIT` 单元裁样。

### ⑥ 矿物带窄舌相位黑杠（R54，111D PROFILE 灰岩段内白云岩舌 6619/6635/6797 等）
- **现象**：用户"部分点灰岩纹理纵向间距不一致，呈现颜色深或暗，一眼看出来"。
- **根因**：PROFILE 矿物带内白云岩舌（孤立 1-6 点、深度延伸 0.15-0.9m < 1 瓦片单元）
  的符号 clip 切片落在瓦片相位随机位置——切到砖缝行=黑色横杠碎片，切到砖腹=几乎不可见
  → 同样宽度的舌深浅随机，且白云岩墨迹本身重 → 观感"深/暗、间距不一致"。
- **修复**：矿物带/余量带游程**深度延伸 <0.8×dy（瓦片单元）时只画底色不裁符号**
  （底色仍在=无空白，R50 原则不破坏；≥1 单元的连续段纹理完整）。修复后窄舌=干净色块，
  宽子带保留完整砖纹（数据真实内容）。
- **教训**：**逐点 clip 切片对"深度延伸<1 瓦片周期"的孤立区域必然产生相位随机的外观**
  ——凡按全局网格铺排+逐点裁剪的绘制，都要对"孤立短游程"做底色化或整单元化处理。
- **检测口径教训**：细粒度扫描（finescan）用**全带宽行墨迹**做峰检测时，成分变化
  （白云岩子带出现/消失）会让峰高过限的行断续 → CV 虚高——**判读前先分清
  "渲染缺陷"与"数据成分变化"**，后者以目检+参照数据列为准。

### ⑥A 楔形过渡区半截纹理（R56，111D 6631-6632 白云岩等；用户："有底色只有部分纹理，纹理不全"）
- **现象**：R54 修复后窄舌=纯底色、厚带=完整砖纹，但**楔形渐变区**（子带宽度在阈值上下
  连续渐变处，如大块白云岩楔形的尖端、水平薄条与厚带之间的过渡）呈现"几行残缺砖纹"的
  半截状态——用户一眼指出"纹理不全，不止一处"。
- **根因**：R54 的纹理/底色判据按**游程**（深度延伸 ≥0.8×dy、游程 max 宽度 ≥0.6×pitch）
  ——同一游程内**逐点子带宽度渐变**：判据用的是游程整体资格，薄处（宽度刚过 0.012 或
  深度上恰 <1 瓦片行）跟着整段走了纹理路径，clip 后露出半行/碎片瓦片。**段级判据 +
  逐点渐变 = 中间状态必然漏网**。
- **修复**：纹理资格**逐点化**——逐点宽度 ≥0.6×pitch 的**连续子段**、且**子段**深度
  延伸 ≥0.8×dy 才画纹理（仍整段一次 imshow+clip 多边形）；宽度/深度不足处只剩底色
  （底色先行已画，无空白）。矿物带与余量带同步。修复后每处只有"完整砖纹/纯底色"
  两种干净状态。
- **教训**：①凡是"整段绘制+逐点裁剪"的链路，**画/不画的判据必须逐点算、再按合格
  性聚段**——段级判据（max/min/整体延伸）在渐变数据上必然产生半残中间态；
  ②修复验证要看**过渡区**（渐变端、交界处），不能只看极端案例（纯尖舌/纯厚带）。

### ⑥B 解释道解释框覆盖低孔留空段（R57c，commit 815815d；111D 盐岩下 1 号油层框）
- **现象**：用户拍板"盐岩下的1号解释层和硬石膏下的2号解释层如果按照 0.06 的截止值
  能分开的地方还是要分开，不符合的也不能解释为油层"——层表早已分开（盐岩下 2 层），
  但**综合图解释道**仍把 6489.9-6496.7 之间 POR<0.06 的 **6.8m 留空段整段框进 1 号
  油层框**（1 号框 6487.6-6505.0），与 6496.7 达标段连成一框。**逐点解释/层表/综合图
  三个出口口径不同步是根源**。
- **根因**：R18 `_fuse_fluid_segments_by_reservoir_unit` 的框顶底取"单元内
  **PHI_DISP>0** 首末深度"——**PHI_DISP>0 ≠ 孔隙度达标**，显示用孔隙度列含截止值
  以下的点；同标签框合并容差 2.0m 也与 logInt 层表 gap_break(0.5m) 不一致。
- **修复**：解释框**逐簇化**——①簇=单元内连续"结论点"（_FLUID_TAGS∪DRY，逐点阶段
  已按分井截止值定案）；②相邻结论点之间夹**留空点（_itp==''）即断簇**（截止值分开
  的一定分开）；NonReservoir 逐点噪声不打断（**R18 兼容**，真隔层由岩性单元边界+
  屏障逻辑负责）；③同标签簇间隔 ≤0.5m（**与层表 gap_break 同口径**）再合并；
  ④簇顶底=结论点首末深度；⑤簇标签=簇内流体结论多数票（与层表多数票同口径）。
  **图面框=层表层的可视化，层表怎么分层图上就怎么画**。
- **验证**：111D 1号框 6487.8-6489.9/2号框 6496.7-6497.0 与层表严格同源；离线复算
  0 个框覆盖 >0.5m 留空段；XIMENIA 框数 48→118 与层表 124 个油气水层基本 1:1；
  两井图面纹理 QC 通过。
- **教训**：①**资格判据必须用"逐点解释结论"（定案产物），绝不能用显示列的">0"当
  资格**；②**多出口（逐点/层表/图面）必须同源**，桥接容差要与解释逻辑对齐，否则
  三处各说各话；③DRY 点图面仍桥接不切框（R18 遗留设计）——若要求"干层不得画进
  油框"需增加 kind 转折断簇，与 R18 噪声场景权衡。

### ⑥C 薄白云岩层仍只留底色（R57d 修订，2026-10-30）

- **现象**：R54/R56 修复后，111D PROFILE 道仍有多处**薄白云岩层只留底色、纹理不全**
  （用户："部分薄白云岩层只有底色，纹理不全"）。典型游程：6602.96-6603.34（0.38m）、
  6766.79-6767.55（0.76m）、6765.26-6766.10（0.84m）、6601.13-6602.04（0.91m）。
- **根因**：R54 把"深度延伸 <0.8×dy（瓦片单元）的孤立短游程"底色化（防相位随机黑杠），
  薄白云岩层属此——底色调好但不画符号，呈"纯色块"。
- **错误修复（已废弃）**：曾尝试 `dy_override=段高` 把薄层行距压缩成"单行纵向压缩完整纹理"。
  **用户指出这违反已定规范**：压缩行距 = 按段高缩放格距，与铁律 #3（格距恒定、不随段长
  放大）直接冲突，纵向间距与厚层不一致。
- **正确修复（R57d 定案）**：**取消 dy_override 纵向压缩**；薄 ref 子段（`z1_clip-z0>0`）
  保持**全局网格正常 dy**（行距与厚层恒定一致，铁律 #3/#7），以 `clip_path` 裁到薄层
  顶底——薄层内显示被边界自然裁切的**完整砖行纹理**（不变量 #4：extent 覆盖完整格行、
  可见性交 clip）。非 ref 类（brick/slant_brick 矢量）维持原 0.8×dy 口径不动。
  `_draw_pattern_seg` ref 分支改为"有正深度即绘制（全局网格+clip）"，不再有"薄层只
  留底色"分支。
- **教训**：①**铁律 #3「格距恒定」禁止一切"按段高缩放行距"**——无论放大（R33 旧 bug：
  厚泥岩横线周期 8pt vs 互层 4pt）还是压缩（本次 dy_override）都违规；②薄层纹理的正确
  形态 = **全局网格 + clip 截出的部分砖行**（边界自然裁切的完整砖行），不是"按段高重排
  的完整纹理"；③任何"薄层特殊处理"方案必须先对照铁律 #3/#7 + 不变量 #4 评估是否破坏
  格距恒定，不能只看"有没有纹理"——这是 R57d 被用户一票否决的根因；④薄层 <1 瓦片周期
  时可能落在砖缝相位（纹淡），但底色仍在、行距与全局一致，属规范允许的"部分砖行"而非
  缺陷。

### ⑥E 符号物理尺寸不足——页面钳制压缩链路下瓦片糊化（R68，2026-11-09）

- **现象**（用户："泥岩短线大小/深浅不一、砂岩点行距不一依然没有解决，如 2440m 这一排泥岩小短线，看得很模糊"）：R67c/d 修复"行间不一致"后，符号整体仍偏小偏淡。
- **根因链（离位复现取证）**：综合图页高 473in > PDF 规范 200in 上限 → `_save_single_page_pdf` `_scale=min(1.0, 14400/max(w,h))` 钳制到 0.42x → 150dpi 图变成页面有效 355dpi 栅格 → 屏幕 100%（96dpi）整页再压缩 ~3.7 倍 → 10x18 瓦片里 1.4px 列隙、3px 线厚被插值糊掉。**渲染数学本身完全正确**（离位复现 `_r68_repro.py` 量出 18px 行距/6px 线长分毫不差）——问题是"符号物理尺寸太小"，压缩后不可分辨。
- **修复**：①`_SYMBOL_REF_UNIT` 单元瓦片按参考图原始 motif 比例放大：Shale 512²（一格 73x128、短线 63x23、列隙 10px）→ 20x30 单元（线长 17px/线厚 5.4px/列隙 2.7px）；Sandstone 128²（点 Φ10/格 16）→ 54x54（点 Φ6.4/隙 3.2px）——压缩显示后仍可分辨；②`_lith_ink_tile` 瓦片掩膜重采样阈值由固定 0.5 改**墨量守恒分位阈值**（`_t=np.quantile(_cov, 1.0-_frac)`，`_frac=_cm.mean()` 钳 0.01-0.6）——点/短线不因砖缝相位在 0.5 上忽粗忽细，瓦片墨量与参考图同比例。
- **教训**：①超长图必经 200in 页面钳制，**符号尺寸要按"压缩后仍可分辨"设计**，不能只验证 1:1 渲染正确；②目检判读 PDF 内符号尺寸时先换算页面压缩比（1pt 渲染分辨率=1/压缩比 图内像素），避免把行距误读数倍；③"行间不一致"（R67c/d）与"整体糊小"（R68）是两层独立缺陷，修一层不等于修另一层。
- **验证**：门禁 `_test_symbol_texture.py` PASS（含注错演练）、run5 图面纹理 QC 通过；2440m 泥岩道 20x30 瓦片行距 30px、线厚 ~5px。

## 4. 渲染门禁 `_test_symbol_texture.py`（改渲染链路必跑）

**检测项（合成井：6 岩性×厚/薄段 + 1m 互层堆叠，两道均跑）：**

| # | 检测项 | 阈值 | 抓什么 |
| --- | --- | --- | --- |
| 1 | 整段墨迹总率 | < 0.01 | 纯底色无符号（R48 类） |
| 2 | 内部 24×24 格墨迹率 | < 0.015 | 大面积空白/成段缺行 |
| 3 | 行距均匀性（R51 新增） | CV>0.18 / 空缺>2.2× / 粘连<0.45×中位 | 间隔不一致/密集发黑（R50 类） |
| 4 | 互层堆叠最长无符号空隙 | > 16px | 薄层整层无符号 |
| 5 | 注错演练（R51 内置，每轮必跑） | 演练 A（逐块锚定+子段<1 瓦片行）CV=0.29 命中；演练 B（blank 纯底色）墨率 0 命中 | **检测器自身失效 → exit 2** |

**关键经验：**
- 墨迹判定用**相对区域中位色**（曼哈顿距离>120）——泥岩横线深绿 vs 底色差仅 133，绝对暗色阈值漏检。
- transData 原点左下 vs 数组行原点顶端——**必须 y 翻转**（曾因未翻转读镜像区域碰巧 PASS）。
- 薄段(<60px)落瓦片空白相位属正常，跳过断言（真井由相邻段接续补齐）。
- **合成数据矿物值要逐点抖动**（1.0/0.78/0.92/0.66…）——旧门禁恒 1.0 根本不触发逐点切分路径，
  R50 类缺陷漏检的根因之一；PROFILE 段级提取 xrange 取带内 (0,0.60)，防带外留白（距中位色 146>120）被误计墨迹。
- **注错必须复现"子段<1 瓦片行"的真实受害形态**：块高大于行距时相位偏差被块内均匀行稀释
  （CV 仅 0.094 漏检）——演练数据要按真实受害比例设计。
- 互层堆叠逐行中位色取墨迹（背景随层变化），不能用整段中位色。

## 4A. 检测焊进出图流程（R52，2026-10-30）

**背景（用户定案）**："这是可视化的问题，也是已经多次反复"——R48 底色、R49 断行、R50 密疏
三轮全是出图后靠用户肉眼发现，说明"改渲染链路必跑门禁"靠纪律守不住。R51 已把三类缺陷
做成自动检测并注错自验，R52 把检测焊进流程：

1. **门禁自动触发**（logvis `ensure_render_gate()`，`_render_log_plot` 入口调用）：
   logvis.py 或 `_test_symbol_texture.py` 的 mtime 比上次门禁通过时间戳（`_gate_pass.stamp`）新
   → 出图前自动跑合成井纹理门禁；**FAIL 即中止出图**（RuntimeError），PASS 写时间戳。
   门禁脚本缺失的部署环境跳过并记 debug 日志（不阻塞生产）。
   效果：改了渲染代码忘跑门禁 → 第一次出图自动补跑；门禁不过 → 根本出不了图。
2. **出图前图面 QC**（logvis `figure_texture_qc(fig, well_name, data)`，`fig.canvas.draw()` 后、
   保存前调用，报告不阻断）：对打 `_lith_qc` 标记的符号道（岩性道=整宽 3%-97%、
   PROFILE 道=矿物带左缘 2%-20% 窄条）逐 1400px 窗（步 700px）做行距均匀性
   （CV>0.5 / 空缺>3×中位行距）与整窗墨迹（<0.004 疑似纯底色）检查；
   异常窗写 `logger.warning('图面纹理QC: <深度> ...')` 并记入 `results['render_qc_warnings']`。
   - 阈值比门禁宽——本 QC 无逐段岩性符号信息，只报"肉眼可见"级异常，精细判定归门禁；
   - 跳过窗口：主岩性属天然不规则类（火成岩人字纹 basalt/ign…、蒸发岩 dash 类 halite/anhy）
     或主 VALID_CURVES_COUNT<3（岩性道合法留空，R33）；
   - **R52b 校准**：分段必须用岩性游程（`_contiguous_lith_runs`）而非固定窗口——不同岩性符号
     天然行距不同（砖纹/点阵/横线混在一个 1400px 窗里 CV 必然虚高，111D 实测假阳性 9 窗）；
   - **R52c 校准**：行距断言仅限**岩性道**——PROFILE 道是矿物比例**堆叠带**，各矿物子带宽度
     随深度变化，任何固定窄条都会横穿移动的子带边界混入不同符号行距（111D 实测 4 条灰岩
     游程假阳性，rowcheck 证伪）；PROFILE 带行距由门禁的合成矿物抖动场景把关，QC 侧只查空白；
   - 窗口/段高阈值：段高<180px（≈5m）不做行距断言，薄段由相邻段接续；深度由 axes ylim 线性映射。
3. **两道防线分工**：门禁（合成数据，阈值严，注错自验，FAIL 阻断）管"代码改动"；
   出图 QC（真实数据，阈值宽，只报告）管"数据形态×代码"的意外组合与 GUI 路径。

## 5. 工程纪律坑（渲染工作流专属）

1. **行结尾以实测为准**：logvis.py 现为 **CRLF**（曾记 LF 已过时）、logInt.py CRLF、
   `_test_symbol_texture.py` LF。补丁脚本统一加 `\n`→`\r\n` 转换层，改前先数 `CRLF/bare LF`。
2. **Bash heredoc 会把 `\r\n` 改写成 `/r/n`**——多行补丁一律写补丁文件（`_dbg/_rXX_patch.py`）再执行，
   应用后 `py_compile` + 验证锚点命中数。
3. **改渲染判据后必跑**：门禁 → 111D 重出 → rowcheck 逐窗对比 → XIMENIA 回归（两井口径）。
4. **GUI 与 CLI 输出目录不同**（`Desktop\output\<井名>\` vs `F:/360/src/output/<井名>/`）——
   对比"用户看的版本"先确认时间戳与来源。
5. **PDF 排障三板斧**：深度刻度序列标定 y 映射（验证线性度）→ 全宽行确认道布局 →
   行距定量扫描。fitz 渲染 dpi 与裁剪窗口要留边（±2px 裁掉边界抗锯齿）。
6. **本地脚本不入库惯例**：`_*.py`（门禁/复现/补丁脚本）不 commit；logGraph.py、
   symbol/company.png 属另一工作线，勿混入渲染 commit。
7. 检测器"碰巧 PASS"比 FAIL 更危险：任何新检测器必须先跑注错演练证明能抓历史缺陷
   （R49 演练曾因 y 轴未翻转读到镜像区域假 PASS）。
