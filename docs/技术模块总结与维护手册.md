### 0.3 修改同步规则（强制）
任何功能修改必须做到"**四同步**"：
1. **代码**：改实现并保持"单一裁决/单一来源"（结论只在 `arbiter` 一处确定）；
2. **配置**：参数/阈值外置到 `logint.json` 或井 `info.json`，写清默认值与单位；
3. **测试**：更新/新增对应自检（单元、契约、报告黄金、验收/回归至少跑一项）；
4. **文档**：更新本手册对应章节 + §12 变更记录；重大流程变化同时更新 `docs/系统架构与产品路线.md`；每次改动在《P0执行记录》追加一轮记录。

提交信息格式建议：`<type>(<module>): <动作/原因>；验证：<测试/指标>；文档：<章节>`。  
**禁止**只改代码不改文档；**禁止**新增独立程序/入口（所有能力作为既有程序的功能）。

## 1. 系统流程与数据契约

### 1.1 主流程（logInt.run_workflow）
```
LAS/DLIS 加载 → 单位/非法值/深度清洗 → QC
→ VSH/孔隙度/饱和度/矿物反演（按剖面类型）
→ 岩性识别（规则 + 元素矿物 + ML + 区域约束）
→ 流体规则解释（截止值/分带/干层/气测图版）
→ 分带/油气同层拆分/重力分异整饰
→ 唯一裁决 arbiter（rules/ML/auto，见 info「解释来源」）
→ 后处理：解释井段裁剪、气田先验、Sg/So、不确定性复核、录井图气测证据、地层顶
→ canonical 层表/CSV/LAS → 可视化（quicklook/综合图/交汇图）
→ 决策记录 + 完整报告（HTML/PDF）→ 运行清单/运行状态
```

## 2. 数据加载、清洗与 QC

### 2.1 实现
- 加载：`logInt.py` 中 `DataLoader`（LAS/DLIS/CSV；曲线别名 `CURVE_NAME_ALIASES`）；
- 清洗：`logsys/clean.py`（`clean_well` 一次完成）；
- QC：`DataLoader.data_quality_check()`，输出 QC 报告；清洗与 QC 通过链接项 `data_cleaning` 关联。

### 2.2 方法（clean.py）
1. **单位归一**：CAL/BS mm→in；NPHI 小数→%；RHOB kg/m³→g/cc；DT us/m→us/ft（按列名/量级判断，记录到报告）；
2. **非法值清洗**：物理范围裁剪/置空（GR、RT、DEN、CNL、DT、POR、SW 等）；识别 `-999/-9999/ICV/IHV` 等哨兵；
3. **深度清洗**：去重、排序、空深度剔除；
4. **厂家退化结果隔离**：POR 中位≤0.02 或 SW 中位≥95%、且有效占比≥70%、有原始曲线 → 原列重命名 `*_VENDOR`，由程序重算（RP-13 案例：SW 100→0.14–0.19）；
5. **输出报告**：行数、单位修正、非法值计数、隔离列 → `<井>_data_clean_report.json`。

### 2.3 QC
- 检查项：深度单调/重复、必需曲线、值域、曲线有效性、数据充分性联动；
- 评分/等级：`quality_level`（GOOD/FAIR/POOR 等）、`overall_score`；QC 报告 `<井>_qc_report.json`；
- 充分性门禁（`logsys/sufficiency.py`）：核心曲线覆盖率 ≥80% OK、≥50% DEGRADED、<50% INSUFFICIENT（RP-13 实测 12%→INSUFFICIENT，结论仅供参考）。

### 2.4 修改点与坑
- 改单位/别名：`CURVE_NAME_ALIASES`、`normalize_units`；改完必须跑 `logsys.test_clean` + 至少一口实井；
- 厂家列隔离误伤：核对"有效占比"而不是全序列占比；
- `IS_CASING` 可能含 NaN → 布尔掩码前必须 NaN→False；
- processed 数据个别 MD=NaN 行：出图/出图版前需 dropna 取有效深度（已修复 logvis）。

## 3. 岩性识别

### 3.1 实现
- 规则/证据：`logInt.py` 岩性识别（GR/VSH/PE/DEN/CNL/DT、元素矿物VOL_*、岩性证据）；
- ML：`logsys/lithcal.py`（训练/交叉验证）、`logsys/pipeline_lith.py`（主流程应用）；
- 区域约束：`logsys/region_lith.py` + `logsys/knowledge/region_lithology.json`；
- 真值/评估：`logsys/truth_lith.py`、`logsys/lith_validate.py`。

### 3.2 方法
1. **规则识别**：按剖面类型（sand_shale/carbonate/evaporite_igneous/mixed）选矿物组合与判据；无判据命中时**默认 unknown**（禁止默认泥岩）；低分兜底：GR≥110/VSH≥0.55→shale、GR≤75/VSH≤0.20→sandstone，否则 unknown；
2. **元素测井矿物**：VOL_CALCITE/VOL_DOLOM/VOL_ANHY/VOL_BASALT/VOL_SALT/VOL_ILLITE 等覆盖>50% 时作为岩性/真值来源；
3. **ML**：特征基础曲线 + 滚动统计（M11/S11/M31），ExtraTrees(500, leaf=2)，5 折分块 CV；应用时平滑窗 11 + 区域约束；
4. **区域约束**：只约束 unknown（不硬改已识别点），记录证据；
5. **真值来源分级**（truth_lith）：岩石分析 0.95/±1m > 元素矿物 0.90/±2m > 录井图结构化 0.80/±3–5m（≤10m）> 录井图 PDF 0.75；
6. **评估**：`lith_validate` 输出准确率、macro-F1、precision/recall、混淆矩阵，及 accuracy_large(≥2m)/accuracy_thin(<2m)、最佳深度平移（±10m）。

### 3.3 关键数据/配置
- `data/calibration/lith_models/<井>.joblib/.json`；`data/calibration/lith_out/*_processed_lithML.csv`；
- 真值：Trakes `岩性解释剖面.xlsx`、111D `*_mineral_lith_truth.csv`、录井图 PDF（masterlog 解析）；
- 输出列：`LITHOLOGY`（最终）、`LITHOLOGY_RULE`、`LITHOLOGY_MC`/`LITHOLOGY_ML`（按链路）、`LITH_EVIDENCE`。

### 3.4 修改点与坑
- 新增井真值/训练：`lithcal.fit_well(well, prof, proc)`；重训后必须看 CV 与层/大段/薄层三指标；
- 薄层不要求准（录井图薄层不可靠），大段必须稳；
- 录井图与测井深度系统误差 ±3–5m（≤10m），对齐容差在 `truth_lith`；
- 元素测井矿物阈值/剖面类型在 region_lithology.json 与 `lithcal` 特征配置。

## 4. 测井解释（油气水）

### 4.1 规则解释
- 实现：`logInt.py`（`build_interpretation_rules`/解释段）；
- 截止值：`por_hc`、`por_dry_max`、`sw_hc`、`sw_deny`、`rt_gas`、`rt_oil`、`rt_water`、`por_gas_min`（气/油孔隙度下限）；
- 结论：GAS / GAS_OIL / OIL / OIL_WATER / WATER / DRY / NonReservoir；
- 分带：区域流体分带（如 BET-1 ft、111D m、RP-13 自动井段+气田先验）可在 `info.json 区域知识`/`区域标定`；
- 干层：低孔低渗+不可采，**不是不含油气**（Sg/So 仍计算，见 §4.7）；干层数量需受控（不能太多）。

### 4.2 气测图版（C1–C5）
- 实现：`logsys/gasplate/`（`engine.evaluate_points/evaluate_layers/fuse_with_log`；`methods`：Pixler 比值、C1/重烃、C2/C3、3H、气体评价）；
- 规则：气/油由**图版决定**，REG 仅作证据；图版无依据时保留测井结论并标 `GAS_REVIEW`，禁止强制降油；
- 干气补充（孟加拉干气）：C1/C2>50 且 C2/C3<1 或 C3≈0 → GAS；
- 输出：`PLATE_FLUID/PLATE_CONF/PLATE_WHY`。

### 4.3 ML 解释
- 实现：`logsys/wellcal.py`（fit/apply，RF/DT，5 折 CV，特征 GR/PHI/SW_COMP/SW_LOG/LOG_RT/VSH）、`logsys/pipeline_ml.py`（主流程）；
- 模型：`data/calibration/models/<井>.joblib/.json`；CV 写入 meta；
- 重要：数据清洗/曲线口径变化后**旧模型会失配**（Trakes 实例：清洗前模型→16.5%；按井重训→97.2%）；改清洗/曲线后必须重训并复跑验收。

### 4.4 唯一裁决（arbiter）
- `logsys/arbiter.py`：读 `info「解释来源」`（rules/ML/auto）；auto 时按模型 CV（≥0.80 用 ML）选择；候选 rules/ML → canonical + `_interpretation_decision.json`；
- 点级 INTERPRETATION 与层表同源；单一来源，禁止多处改结论。

### 4.5 后处理（统一入口）
- 分带/油气同层拆分：`zonation.py`、`mixed_split.py`；
- 重力分异：`enforce_fluid_segregation`（气上/油中/水下；GAS_OIL 气在上）；
- 解释井段裁剪（自动=裸眼+电测覆盖；info 优先）；
- 气田先验（邻井试油均气井）：OIL/GAS_OIL→GAS（点级+层表同步）；
- 录井图气测异常证据：`MASTERLOG_GAS` 标记，不强制改判；
- 地层顶（设计）→ `FORMATION` 列；
- 不确定性复核清单：薄层/气测异常非气/图版冲突 → `UNCERTAIN` + `<井>_review_list.csv`。

### 4.6 层表
- `logsys/layers.py::build_layers`：最小层厚、薄层吸收（同族才合并，不跨族）、`THIN/BELOW_MIN_THICK` 标志；
- 字段：TOP_MD/BASE_MD/THICKNESS/LITHOLOGY/INTERPRETATION/GR_MEAN/VSH_MEAN/PHI_MEAN/SW_MEAN/RT_MEAN/SG_MEAN/SO_MEAN/SWE_MEAN/REVIEW_FLAG 等。

### 4.7 Sg/So 与守恒（用户定案）
- `logsys/fluids.py::compute_sg_so`：
  - GAS：Sg=1−Sw；OIL：So=1−Sw；
  - **GAS_OIL=油气同层（测试油气同出、比例大体相当）：默认 Sg/So 各半**；如实际测试比例不同，可在 `info 解释参数.气油比例` 指定（0.4=气占40% 仅示例，不是固定规则）；**不用气测组分自动推断饱和度比例**；
  - **干层 DRY 仍含烃**：按 1−Sw 计算并按图版/比例分配（物性差/不可采 ≠ 无油气）；
  - 守恒：`SW_EFF = 1−SG−SO`，SG+SO+SW_EFF=1（Sw 实测保留）。

### 4.8 修改点与坑
- 改阈值/规则：优先放 `logint.json`/`info.json`，不硬编码；
- RT 取值：无 RT 用最深阵列（RAL5→RAL1，按用户口径）；曲线别名补 `CURVE_NAME_ALIASES`；
- 气测图版 DRY 与"干层"不是同一概念（Pixler 无区间≠无油气）；
- 薄层/水层互斥、干层不能吞掉真实油气层；改后跑 `test_interpret_rules`/`test_mixed_policy`/验收；
- 层表/点/图/报告/验收必须同源（canonical）。

## 6. 气测解释与气体可视化（Gas/Flair）

### 6.1 程序定位与文件
- **Gas.py**：C1–C5 气测解释程序（传统/ML/DL/验证/可视化/完整流程）；
- **Flair.py**：C1–C8 气测解释程序（QC/传统/ML/验证/可视化/工作流/API）；
- **GasInterpretation.py**：历史并行气测解释实现（144KB，逐步并入 Gas/Flair 共用库，避免双份口径）；
- **gas_constraint.py**：历史气测约束模块（69KB，主链路已改用图版库；迁移时核对）；
- 与 logInt 共用 `logsys/gasplate/` 方法库（不新增程序；后续逐步统一）；
- 图版配置：`logsys/gasplate/config/gas_plate_default.json`；培训资料 `FLAIR解释.pptx`。

### 6.2 方法库（gasplate）
- `engine.evaluate_points/evaluate_layers/fuse_with_log`；配置 `gasplate/config/gas_plate_default.json`；
- `methods`：Pixler（C1/C2、C1/C3、C1/C4 油气区）、C1/重烃比、C2/C3、3H、气体评价；分层统计；
- 干气补充（logInt 内）：高 C1/C2、低 C2/C3 → GAS；
- 输出：PLATE_FLUID/OIL/GAS/DRY/UNDEFINED + 置信度 + 原因。

### 6.3 与录井图/可视化
- 录井图气测异常：`well_docs`/`masterlog` 提取 Gas Show/Gas Break 区间→`<井>_masterlog_gas_zones.csv`，按厚度+TG/C1 幅度分级（主气层/显示段/弱显示）；
- 证据：`MASTERLOG_GAS_SHOW` 点列、层表 `MASTERLOG_GAS` 标记；
- 气体可视化：quicklook/综合图气测道、图版结果道、干气/湿气/荧光显示标记。

### 6.4 修改点与坑
- 图版阈值必须按图版/config 调整，不硬编码；改后跑 `gasplate/test_gasplate`；
- 气测与测井深度系统误差 ±3–5m（≤10m），对齐用 merge_asof + 容差；
- Pixler 区间不覆盖干气（C1/C2 可 >50），注意 DRY 与干层语义；
- Gas/Flair 与 logInt 的字段口径要一致（C1–C5/C1–C8、单位 ppm/%）。

## 8. 井文档（地质设计 / 录井图 / 甲方格式）

### 8.1 唯一模块 `logsys/well_docs.py`
- `read_design`：井名/气田/井型/设计井深/构造/目的层/目标井段/套管/流体界面/地层顶/预测地层序列/设计目的/区域地质/井位/来源/置信度；
- `read_masterlog`：岩性层+气测异常事件/井段+图头（公司、服务商、日期、井深、井型、泥浆、井身结构、图例）；
- `read_client_format`：甲方 quicklook 格式/图例（显式选择 > 井目录查找 > 跳过）；
- `sync_info_json`：将结果写入 `<井>info.json` 三分区（可读可改），首次只补缺失、保护手改；
- `build_context`/`load_context`：合并 info+设计+录井图+格式，缓存 `<井>_well_context.json`（info 修改后失效重建）。

### 8.2 规则
- 其它程序**只调用** well_docs，不重复解析；masterlog.py 仅被 well_docs 调用；
- 未选择→井目录查找→都没有跳过（不弹窗/不报错）；
- 解释井段优先级：`info 解释井段` > 地质设计目标井段；设计/masterlog 仅作证据，不强制改结论；
- 深度容差：录井图 ±3–5m（≤10m）。

### 8.3 修改点与坑
- 新国家/公司格式：优先扩正则/字段表，别改其它模块；
- info.json 中文配置映射回内部字段；修改后下次运行生效（缓存按 mtime）；
- 地层顶常只有名称无深度（GTO 表格图像）→ 如实标注缺深度，不臆造。
