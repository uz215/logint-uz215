# 知识沉淀元原则（K-SYS-001）

## 一、知识的三层来源与地位

1. **用户口述标准/要求**：是知识源（例如"煤=三高两低+尖峰状"、"交会图流体面板只用储层数据"），但**可能片面、可能不对、可能只适用于特定区域**——不能直接当成永久真理。
2. **井数据验证**：口述知识必须经井数据复核（双井回归：有该岩性/流体的井 + 无该岩性/流体的井）验证后，才固化为程序判据。
3. **知识库知识**：验证后的知识按本条目库格式沉淀（id/scope/status/version/校正历史），进入 Whoosh/向量检索，并绘制成知识图谱。

## 二、知识条目生命周期

```
口述（草稿）→ 井数据验证（试行）→ 双井回归通过（已验证）
   → 新证据/新井反馈 → 修正（已修正，version+1，旧结论记入校正历史）
   → 被证伪 → 废止（已废止，留痕不删除）
```

- **status**：试行 / 已验证 / 已修正 / 已废止。
- **scope**：全局 / 剖面类型（sand_shale、carbonate）/ 区域 / 单井。区域性知识**必须标注 scope**，禁止静默全局化。
- **校正历史**：每一次修改都在条目正文「校正历史」追加一行（日期 + 改了什么 + 为什么 + 依据哪口井），形成可追溯链。

## 三、判据落地的配套铁律（与 logInt.py 实现绑定）

- **deny 原则**（R34 定案）：排除性证据一律写 deny，must 只留物理底线；井级自适应阈值只放 deny；每改判据必须双井回归——判据演进不反复。
- **区域知识**（R36 定案）：区域认识写入 `<井名>info.json`「区域知识」组，标注"无"是最强约束，优先于单点判据。
- **排除理由需证据**（R35 定案）："扩径造成"类排除必须带井径条件等直接证据。
